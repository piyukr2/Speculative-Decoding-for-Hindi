Speculative Decoding

How can a large language model verify several future tokens in one forward pass if text generation is autoregressive? The answer is the difference between generating unknown tokens and evaluating tokens that have already been proposed.

One-sentence answer: The draft model proposes a short sequence autoregressively. The large teacher/target model then processes the prompt plus all proposed tokens in one Transformer forward pass, producing a next-token distribution at every position in parallel. A causal attention mask ensures each position only uses its own prefix.

1. The big picture: two different jobs

In ordinary decoding, a model predicts one token, appends it to the context, and runs another decoding step. Speculative decoding divides the work between two models:

3. Why can the target model evaluate multiple positions at once?

A Transformer layer processes a sequence as a collection of position representations. During a forward pass, matrix operations for many positions can be performed together on the GPU. The model does not have to wait for the target model to generate each proposed token, because the draft has already supplied those token IDs.

For the sequence The cat sat on the mat, the target model can calculate all of these next-token distributions in the same pass:

P(sat | The cat)
P(on | The cat sat)
P(the | The cat sat on)
P(mat | The cat sat on the)

Each expression is a different prediction position. The input sequence is known, so the target model can calculate hidden states and logits at all positions together.

Important distinction: Parallel evaluation does not mean the target model magically knows the future. It is conditioning on the draft's proposed future tokens. If a proposal is wrong, later predictions conditioned on that proposal may not describe the sequence the target would have generated on its own. The acceptance/correction algorithm handles this.

What happens inside a forward pass?

  1. The prompt and draft tokens are supplied as one token sequence.
  2. Embedding and Transformer layers process the sequence positions together.
  3. At each position, the model produces logits (scores for possible next tokens).
  4. Those logits are converted to probability distributions and used to verify the draft proposals.

4. The causal attention mask: no looking into the future

Autoregressive Transformers use causal attention. A position may attend to earlier tokens and itself, but not later positions. The model can still compute every row of this attention pattern in parallel.

The diagonal ✓ means a position can use its own token representation to compute the hidden state that predicts the following token. The actual mask also includes all preceding prompt positions.

Why is this not a contradiction?

“Causal” describes which information each position may use—not the order in which the hardware must calculate every position. Since the input token IDs are already present, the model can calculate all permitted attention operations in parallel without allowing future-to-past information flow.

5. What does “verify” mean?

Verification is not simply checking whether a proposed token is the target model’s single most likely token. Standard speculative sampling uses a probability-based acceptance rule so the overall output distribution matches the target model’s distribution.

  • Accepted prefix: A run of draft tokens can be accepted from the start of the proposed block.
  • Rejection: If a proposal fails the sampling acceptance test, the algorithm samples a correction token from a distribution designed to preserve the target model’s distribution.
  • Bonus token: If every draft token is accepted, the target model can often sample one more token from the distribution after the final proposal.
Do not confuse two ideas: the target model computes all the needed distributions in parallel, but the algorithm’s acceptance process still determines how many tokens from the proposed prefix can be committed.
Is it enough to compare draft and target top-1 tokens?

No. Matching top-1 tokens is a useful intuition for a simplified explanation, but it is not the full standard algorithm. Exact speculative sampling uses the draft and target probability distributions, random acceptance decisions, and a correction distribution on rejection.

6. Why can this be faster?

Ordinary target decoding

Target predicts one token → next target step → next target step…

Many sequential target-model invocations.

Speculative decoding

Draft proposes a block → target verifies the block in one pass.

Fewer sequential target-model invocations when acceptance is good.

Large-model decoding can be limited by memory bandwidth and the overhead of repeatedly launching small inference steps. Processing several positions in one target pass can use the GPU more efficiently and reduce the number of sequential target calls.

However, speculative decoding is not guaranteed to be faster. Performance depends on draft-model cost, how many proposals are accepted, sequence length, batching, hardware, and implementation details.

Takeaway: The draft model pays the sequential cost of guessing. The target model pays for a parallel verification pass. The method is useful when that verification pass costs less than generating the same number of tokens one at a time.

8. Final mental model

  1. Unknown tokens must be generated autoregressively: the draft model proposes them one at a time.
  2. Known proposed tokens can be evaluated in parallel: the target runs one forward pass over the whole proposed block.
  3. Causality is preserved: the causal mask prevents each position from using later tokens.
  4. Sampling correctness is preserved: acceptance and correction rules keep the output distribution aligned with the target model.

Remember: “parallel verification” means parallel computation of next-token distributions for a known proposed sequence—not parallel generation of arbitrary future text.
